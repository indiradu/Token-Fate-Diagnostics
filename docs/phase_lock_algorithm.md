# PhaseLock staged algorithm design

## Research question

PhaseLock treats three decisions as separate:

1. **Semantic/token lock:** should position `i`'s current token identity become
   irreversible?
2. **Representation/reference lock:** after identity commitment, should the
   position's hidden state and derived K/V reference stop changing?
3. **Compute lock:** after reference locking, which query/FFN rows can be
   removed while active positions continue attending to the frozen reference?

The implementation uses a nested replay protocol. A semantic plan is generated
with dense computation and replayed by the representation and compute arms. The
representation plan is generated by the dense A2 backend and replayed by A3.
This keeps the A1/A2 and A2/A3 comparisons matched on irreversible choices.

## Phase 1: semantic/token identity

The current controller accepts the top prediction for the scheduled number of
positions, with an optional early-lock fraction. The registry contains:

- `confidence`: top posterior probability;
- `posterior`: confidence discounted by one-step posterior KL;
- `token_fate` / `trace`: confidence discounted by a learned future-stability
  risk predictor;
- `margin`: top-1 minus top-2 probability;
- `persistence`: confidence multiplied by repeated top-1 persistence;
- `consensus`: confidence, KL, persistence, and top-1 flip combined.

All policies write the same online measurements. `token_fate` and `trace` are
only enabled when a predictor trained on disjoint completed traces is supplied.
The future-stability label is explicitly a model-trace label, not a guarantee
of task correctness.

## Phase 2: representation/reference

After a semantic commit, the identity remains fixed but its hidden state is
still recomputed. At a later step, the representation controller observes
cosine drift at a configurable transformer layer. The default rule requires
drift below a threshold for consecutive observations (`patience`) and a minimum
post-commit age. Controls include posterior-only and confidence-only gates.

The named drift-gate presets are:

| Gate | Threshold `τ` | Patience | Minimum age | Meaning |
|---|---:|---:|---:|---|
| `strict` | 0.005 | 4 | 1 | accepts only very stable representations |
| `default` | 0.020 | 2 | 1 | current middle setting |
| `loose` | 0.050 | 1 | 1 | accepts more drift after one confirmation |
| `very_loose` | 0.100 | 1 | 1 | stress test for premature reference freezing |

Thus “looser” is not a vague confidence setting: it increases the allowed
cosine drift and reduces temporal confirmation, while still requiring one
post-commit update.

This separation is important: semantic commitment can be correct while the
representation remains a live dependency for other positions.

## Phase 3: compute

The compute backend has three explicit modes:

- `dense`: recompute all rows;
- `kv_cache`: freeze reference rows and retain their K/V for active queries;
- `row_sparse`: reuse frozen K/V and compute only active query and FFN rows.
- `row_sparse_packed`: the same row intervention using persistent preallocated
  K/V workspaces and packed active-row projection writes.

The current `row_sparse` backend still assembles a full attention K/V tensor and
uses the dense attention kernel. `row_sparse_packed` removes repeated workspace
allocation and scatter setup, but still calls the same dense attention primitive.
Both are correctness and systems audits, not claims of an optimized production
sparse kernel. Wall-clock gain is measured after CUDA synchronization and is
reported separately from NFE and logical active-row counts.

## Logging contract

Each run writes:

- `run_config.json`: every dataset, model, threshold, policy, and seed;
- `A0.jsonl`, `P1_*.jsonl`, `P2_*.jsonl`, `P3_*.jsonl`: output, answer score,
  token IDs, NFE, latency, and lock counts;
- `phase_ledger.jsonl`: semantic decisions, representation observations,
  reference-lock decisions, online confidence/KL, drift, threshold, age,
  patience count, and compute policy;
- `phase_plans.jsonl`: the exact semantic/reference plans replayed across arms;
- `analysis/`: paired sequence, answer, NFE, and runtime metrics.

## First experiment matrix

The first smoke matrix should use LLaDA-8B-Instruct on GSM8K, MATH500, and
HumanEval with identical step and generation settings. Run confidence,
posterior, and consensus first; add token-fate/trace once the disjoint trace
predictor is supplied. Sweep representation thresholds and patience after the
single-threshold smoke run. A method is retained only if it meets all three
gates: non-inferior task quality, measurable reference/compute savings, and
paired output/answer harm below the preregistered tolerance.

## Relation to existing decoders

LLaDA uses masked iterative denoising with bidirectional attention. SureLock
motivates local posterior-KL locking with cached K/V and skipped query/FFN
rows; Fast-dLLM motivates block-wise approximate KV reuse and confidence-aware
parallel decoding. TraceLock motivates learned future-stability policies for
token commitment. PhaseLock keeps these ideas as separate decision layers so
their assumptions can be audited rather than conflated.

## Implementation changelog

- **v0:** added the four-arm audit and verified that semantic commitment,
  reference freezing, and row removal are separate interventions.
- **v1:** changed the PhaseLock runner to generate one semantic plan in P1,
  replay that exact plan in P2, then replay the exact P2 reference plan in P3.
  This prevents policy differences from being mistaken for phase effects.
- **v2:** added posterior-KL, persistence/consensus, and learned token-fate
  priorities alongside confidence; added drift threshold, patience, and
  post-commit age gates for reference locking.
- **v3:** added per-event JSONL logging and an analyzer that reports paired
  sequence/answer/NFE/runtime metrics plus position-level drift versus A0/P1
  token divergence. A logging correction now records the semantic-policy ID on
  every representation observation; runs made before that correction are
  retained for intervention metrics but excluded from policy-conditioned drift
  claims.
- **v4:** added HumanEval loading and isolated single-sample execution scoring.
  This is an exploratory pass@1 screen, not an official pass@k estimate.
- **v5:** labeled baseline denoising transfers separately from semantic lock
  events, added an explicit arm ID to ledger rows, and made baseline lock
  counts report zero.
- **v6:** added named representation-gate presets and a `row_sparse_packed`
  backend. The packed backend reuses persistent K/V workspaces and preserves
  the exact P2 reference plan for paired P3 comparison.

The current row-sparse implementation deliberately uses a correctness-first
reference implementation: it computes active queries and FFN rows but assembles
a full K/V tensor and calls the dense attention primitive. Therefore a negative
wall-clock gain is a valid systems result for this implementation, but it does
not prove that a fused sparse kernel could not be profitable.
