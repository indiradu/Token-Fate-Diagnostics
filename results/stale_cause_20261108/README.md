Question. On HumanEval 0-163 at 512 tokens with word lock C-0.9, the S32 representation cache (query rows = current block's blanks + rows written on the previous call; prompt, older written-answer and later-block blank rows keep the K/V of the last dense call; dense call at every block start) loses 17 answers and gains 8 against the dense decode (net -9 [-19, +1]). Two analyses ask what causes it. Quality only; speed is not measured.

- **Analysis 1, noise-matched control** (`orchestration/run_noise_control.py`, `analyze_noise_control.py`): the K/V of the cached rows is replaced by fresh K/V (a dense pass over the current tokens), by the real cache, or by fresh K/V plus a random perturbation whose per-row, per-layer norm equals ||stale - fresh|| (x0.5, x1 with two seeds, x2); also a variant that touches only blank rows. Eight arms, all 164 tasks.
- **Analysis 2, oracle repair at the first divergence** (`orchestration/run_oracle_repair.py`, `analyze_oracle_repair.py`): for the tasks the cache loses (17 under word lock C-0.9, 17 under Lctx-0.8), find the first call at which the cached decode writes something different from the dense decode, resume the cached decode from the block-start dense call before it (state rebuilt from the write log) with ONE row class made fresh (prompt / written rows of earlier blocks / written rows of the current block older than one step / next block's blank rows / blank rows beyond / all blank rows / all rows), as an oracle (dense-pass K/V) and as a real computation, for the divergence block only and to the end.
