No decode of this campaign has been seen.

## Words
- WORD LOCK = which blank positions are given a token in a call. Here: C-0.9 (write every blank of the current 32-block with confidence >= 0.9, else the most confident one) for Analysis 1; C-0.9 and Lctx-0.8 (the word-lock agent's learned context rule, never refit) for Analysis 2. The word lock is never varied inside a comparison.
- REPRESENTATION CACHE (REPRESENTATION FREEZE side) = which rows' K/V a call reads from the cache instead of recomputing. **S32**: the query rows of a call are the rows written on the previous call plus the blanks of the current 32-block; all other rows keep the K/V of the last dense call; a dense call (every row) at each block start; first-EOS truncation. LLaDA-8B-Instruct, bf16, temperature 0, block 32, 512 generated tokens, HumanEval 0-163 (164 tasks). Quality only: **speed is not measured anywhere in this campaign.**
- CACHED rows = every row outside the query set of a non-dense call, split into five classes: **prompt** rows; **prior_written** (written-answer rows of earlier blocks); **inblock_old** (written-answer rows of the current block that were written two or more calls ago); **next_blank** (blank rows of the next block); **far_blank** (all other blank rows: blank rows of blocks two or more ahead, and blank rows of the current block that lie outside the query set, which happens only beyond a first-EOS truncation point). Classes are assigned by block index relative to the block being decoded; a first-EOS truncation drops blanks from the word lock but does not move a row between classes, except that the current block's truncated-away blanks (still input rows) are far_blank. The five classes partition the cached rows.
- Reference numbers (existing records, `farcache_stack_20261105/records/stage1.jsonl`): dense C-0.9 solves 68/164; S32:C-0.9 solves 59 (loses 17, gains 8, net -9 [-19, +1]); its text differs from dense on 138/164 tasks (tokens identical on 26). Lost tasks, C-0.9 (17): HumanEval/4, 9, 12, 16, 25, 43, 47, 49, 56, 69, 72, 79, 82, 85, 105, 114, 128. Dense Lctx-0.8 solves 66, S32:Lctx-0.8 solves 57 (loses 17, gains 8); lost tasks, Lctx-0.8: 5, 11, 12, 14, 16, 21, 25, 43, 48, 58, 60, 69, 72, 74, 82, 87, 158. Earlier ablations (diag_he): S32 with a dense call every call + truncation is token-identical to dense; caching only prompt + written rows (every blank row computed every call) loses nothing (+1 [-8, +10]); the measured relative L2 drift of the cached far-blank K/V is 0.15-0.37.

## Analysis 1: noise-matched control (HumanEval 164, word lock C-0.9)
**Design.** At every non-dense call the attention of the query rows reads, for each cached row, a K and a V vector at every layer. K is the post-RoPE key exactly as the cache stores it. Arms differ only in what those vectors are; the caches themselves are never written by the manipulation (the manipulation builds the tensors for the attention of that call), so the stale cache stays the S32 stale cache in every arm. "Fresh" = the K/V a dense pass over the CURRENT tokens would give at that call (a second, scratch engine runs a dense pass before each cached call). The query rows are always computed in the call, as in S32.

| arm | classes manipulated | K/V read for them |
|---|---|---|
| P-fresh | all five | fresh (oracle). Must reproduce the dense C-0.9 decode. |
| P-stale | all five | the cache itself (the dense pass is still run, for the distance statistics only). Must reproduce S32:C-0.9 token for token. |
| P-rand1a, P-rand1b | all five | fresh + a random perturbation with, per row and per layer, K and V separately, norm = 1.0 x ‖stale − fresh‖; direction = Gaussian over the flattened (kv heads x head dim) vector, normalised, then scaled; float32 arithmetic, cast to bf16. Two random seeds: `seed_for(example_id, "a")` and `"b"`. |
| P-rand0.5, P-rand2 | all five | the same with 0.5 x and 2 x the norm (seed "a") |
| B-stale | next_blank + far_blank stale; prompt, prior_written, inblock_old fresh | the cache for blank rows, fresh for the rest |
| B-rand1 | next_blank + far_blank: fresh + 1.0 x noise (seed "a"); the other three classes fresh | |

Perturbation point, fixed now: K (post-RoPE) and V of every layer, layer 0 included (at layer 0 the stale-fresh difference is zero for blank and prompt rows, so the noise there is zero by construction). Rows with ‖stale − fresh‖ = 0 get no noise. Realized norm ratios are logged (expected 1.000 ± 0.01 of the target after bf16 rounding). Per class and layer the relative distances ‖stale − fresh‖/‖fresh‖ are logged from every arm.

**Parity gates.** (1) P-stale tokens equal the stage-1 S32:C-0.9 tokens: 164/164 expected; the process aborts if any of the first 3 tasks differs. (2) P-fresh equals the stage-1 dense C-0.9 tokens (up to the first EOS/EOT): expected on at least 150/164. bf16 GEMMs over a row subset versus all rows can flip a near-tie, so exact equality is not guaranteed; the number is reported and every comparison is also made against P-fresh.

**Readouts.** Answers (HumanEval tests): correct, lost/gained and net against dense C-0.9, against P-fresh and against P-stale, 95% interval by bootstrap over questions (10,000 resamples, seed 23); text-differs share against dense and against P-stale; first differing token against dense; overlap of lost-task sets between arms with its chance expectation; the distance table. N1 = the mean of the two seeds of P-rand1 (per question, correct = (a + b)/2).

**Predictions (point [80% range]; my pre-decode estimates, not findings).**
- Parity: P-stale 164/164 (95% sure); P-fresh tokens equal to dense on 160 [150, 164]; P-fresh net vs dense 0 [-2, +2]; P-fresh text differs from dense in at most 10% of tasks.
- Net vs dense: P-stale -9 (by parity); B-stale -7 [-14, +1]; N1 -3 [-11, +4]; P-rand0.5 -2 [-9, +5]; P-rand2 -6 [-14, +2]; B-rand1 -2 [-9, +5].
- Text differs from dense: P-rand1 0.70 [0.40, 0.95], P-rand0.5 0.55 [0.25, 0.90], P-rand2 0.85 [0.55, 1.00], B-rand1 0.60 [0.30, 0.90]. Realized norm ratio 1.000 ± 0.01.
- Distances (mean over layers 1-31): relative L2 of stale vs fresh K for far_blank rows 0.25 [0.15, 0.40]; blank rows drift more than prompt rows.
- Probabilities: P(N1 net <= -5) = 30%; P(N1 net >= -2) = 50%; P(dose response monotone: net(0.5x) >= net(1x) >= net(2x), point estimates) = 45%.

**Decision rules (applied to the point estimate and the interval; stated before data).** Let netS = net(P-stale vs dense) (reproduces -9), netN = net(N1 vs dense), Δ = N1 − P-stale in answers (positive = the noise arm keeps more answers than the stale cache).
- **A, "magnitude suffices":** netN <= -5 and the interval of Δ contains 0. Reading: noise of the same norm as the stale error loses about as many answers as the real stale cache; the damage does not need the error to be *outdated* context. It does not show the stale error and the noise act through the same mechanism.
- **B, "the structure of the stale error matters":** netN >= -2 and Δ >= +4. Reading: same-norm isotropic noise does not reproduce the damage; the stale error has a damaging structure that random directions lack (it does not say whether that structure is "missing" or "outdated" context, and Gaussian K is off the manifold of real keys, so equal norm is not equal attention effect). Called *resolved* only if the interval of Δ excludes 0.
- **C, "not separated":** anything else, including intervals that contain both A's and B's values. With 164 tasks and netS = -9 the design resolves differences of roughly 8 answers between arms; smaller differences are called unresolved.
- Dose response: reported as the three points (0.5x, 1x, 2x); not used for A/B/C.
- Row-class decomposition: B-stale vs P-stale and B-rand1 vs P-rand1: if B-stale net is within 3 answers of P-stale the blank rows carry the damage the stale cache shows (consistent with the earlier ablation); if B-stale net >= -3 while P-stale is -9, the prompt/written rows are involved after all.
- Parity failure rule: if P-fresh equals dense tokens on fewer than 140/164, the fresh construction is not dense-equivalent on this model and every "vs dense" reading is replaced by "vs P-fresh" (stated in the results).

## Analysis 2: oracle repair at the first divergence (HumanEval 164; lost tasks of word lock C-0.9 and Lctx-0.8)
**Design.** Per task, two decodes with per-call write logs: DENSE (the S32 engine with a dense call every call and first-EOS truncation; token-identical to the dense word-lock decoder up to the first EOS, shown on 164/164 earlier) and CACHED (S32). A call's WRITE EVENT is the set of (position, token) pairs written. The FIRST DIVERGENCE is the first call whose write event differs; its position is the lowest differing position; kind = `token` (both wrote that position with different tokens), `a_only` (only the cached decode wrote it), `b_only` (only the dense decode wrote it: a word-lock set difference). c0 = the last block-start dense call at or before the divergence call (it opens the block of the divergence). Recorded for every task of the census (all 164 for C-0.9; the lost tasks for Lctx-0.8): the divergence call, answer position (token index), fraction of the dense answer length, position in the block, calls after block start.

**Replay.** The state at a dense call is fully determined by the tokens written so far (the dense call recomputes every row and refreshes every cache), so the cached decode is resumed at c0 from the logged writes (`replay_state` + `decode_selective(resume=...)`), including the first-EOS truncation point. Tested on the toy model: resuming at every dense call of the decode reproduces the original tokens, write events and call kinds, with and without an EOS truncation. On GPU every task first runs the NULL control (resume, nothing repaired) and the process aborts if it does not equal the cached decode.

**Repairs** (one class at a time, all with the word lock and the query rows unchanged): (a) next_blank, (b) far_blank ("blank rows beyond the next block", plus blanks beyond a truncation point), (c) inblock_old, (d) prompt, (f) prior_written (added to complete the partition), (e) all cached blank rows (next_blank + far_blank; positive control), (g) all five classes (dense-equivalent control). Two modes: **oracle** = the class's cached K/V replaced by those of a dense pass over the current tokens; **compute** = the class's rows are added to the query rows and computed in the call (the realizable repair, the class then sees the still-stale K/V of the other classes). Two windows: **seg** = only in the calls that decode the block of the divergence (then plain S32 again); **end** = from c0 to the end of the decode.

**Readouts, per class, mode, window.** RESTORED (write events equal dense through the divergence call; i.e. the repaired run's own first divergence from dense is later than the original or absent), POS TOKEN (token at the first divergent position equals the dense token; defined only for kinds `token`/`a_only`), IDENTICAL (final tokens equal dense up to the first EOS), PASSES (HumanEval tests), with the number of tasks where the class was non-empty. Wilson 95% intervals (counts of at most 17 tasks; no bootstrap). Divergence statistics for lost versus retained tasks.

**Predictions (point [80% range]).**
- Census parity: the cached decode with logs equals the stage-1 S32 tokens on 164/164 (95%); the dense engine equals the stage-1 dense tokens to the first EOS on at least 160/164. Null control 17/17 (abort rule above).
- First divergence of the 17 lost C-0.9 tasks: all 17 diverge; kind `token` 55% [35, 80], set-differences 45%; median answer position 40 [15, 90]; median fraction of the dense answer length 0.25 [0.10, 0.50]; median calls after block start 5 [2, 12]. Retained tasks diverge too (138 of 164 differ in text): the divergence itself is common, the loss is not.
- Controls: (g) oracle seg RESTORED on 17/17 [15, 17] (P(>= 15) = 85%); (e) oracle seg RESTORED on 15/17 [11, 17]; (e) compute seg 13/17 [8, 17]; (g) oracle end PASSES on 16/17 [13, 17] (restored dense tokens, whose tests pass by construction).
- Single classes (oracle, seg, RESTORED of 17): (a) next_blank 9 [4, 14]; (b) far_blank 6 [2, 12]; (c) inblock_old 3 [0, 8]; (d) prompt 2 [0, 7]; (f) prior_written 1 [0, 5]. Compute mode restores fewer than oracle in at least 3 of the 5 single classes (65%). PASSES for the best single class in `end` window: 9 [5, 14].
- Lctx-0.8 (17 tasks): same ordering of classes (65%); no separate numbers.

**Decision rules.** A class is called a *carrier* if oracle-seg RESTORED >= 9/17 (lower Wilson bound reported), *negligible* if <= 2/17, *partial* otherwise; classes whose shares differ by fewer than 6 tasks of 17 are called unresolved against each other. The experiment is *valid* only if (g) oracle seg restores >= 15/17 and the null control is 17/17; otherwise the class table is not interpreted (replay or numerics problem) and this is reported as the result. If (e) restores clearly more than (a) and (b) individually, the damage is called *distributed over the two blank classes* rather than carried by one. "Restored at the divergence" says that the first differing write is removed; it does not say the program is correct (PASSES is reported separately) and a single-class repair does not isolate interactions between classes (the sum of single-class shares can differ from the all-class share).

## Not claimed whatever the result
Random-direction noise vs staleness is a control on error magnitude only; an arm that matches S32 does not show that the real stale error and Gaussian noise act through the same mechanism, and an arm that does not match does not identify missing vs outdated context. The oracle repair uses K/V a dense pass would give at that call, which no cache could have without paying for the dense pass; the `compute` mode is the realizable counterpart. n = 164 tasks (68 dense-correct) resolves a net difference of about +-6 answers; the lost-task analyses have 17 tasks per word lock. Nothing here is a speed result.

## Process rules
