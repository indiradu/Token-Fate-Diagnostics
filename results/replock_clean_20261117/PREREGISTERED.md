# Representation-cache study, clean rerun (written 2026-11-17, before any run of this campaign)

Status: PLAN ONLY. Nothing in this directory has been run. Decisions below are the project owner's (2026-11-17 conversation); open points are marked OPEN.

Terms. **Word lock** = which blanks get a word on a call (saves calls). **Representation cache** = which rows' K/V are reused (saves compute per call). Row types: prompt, written, blank. Nothing here uses K4 as a baseline.

Standing rules. Speed comes first; answer parity is acceptable (a gate, not the target). Quality reference = the model's ORIGINAL decoding (one token per step, block 32, no acceleration). Baselines = published rules. Tables sorted by speed. Answer change = paired delta with CI, and whether the CI includes 0; no tolerance imposed (the owner decides tolerance and the primary metric).

## Part A. Study 5: representation caches under ONE shared word lock (first wave)

### A1. Design
- **Word lock fixed to Conf-0.9** for every arm: per 32-block, write every blank with confidence >= 0.9, else the single best blank. (Fast-dLLM's threshold rule is the same up to >= vs >.)
- **Baseline per model = the original decoder** (B0, one token per step, block 32, 512/256 calls). One baseline per model; it is not compared across models.
- **Reference row: dense Conf-0.9** (word lock only, no representation cache) so each cache's extra gain over the word lock is visible.
- **Representation-cache arms (6):** four traditional (published paper or convention) + two ours.
  1. Fast-dLLM dual cache (released code, threshold 0.9 is its own setting). Fast-dLLM prefix cache optional fifth published arm (OPEN: include?).
  2. dLLM-Cache (K_p 25, K_r 5, rho 0.25).
  3. dKV-Cache-Decode (reload every 8).
  4. Elastic-Cache (our engine's reproduction: window 16, Conf-0.9 rule, attention-aware trigger gamma 0.9; no usable released code).
  5. R0 (derived rule, constants frozen).
  6. Learned controller (frozen risk model, budget recalibrated from 10-20 prompts per model).
  dKV-Cache-Greedy cannot run (released code raises NotImplementedError for low-confidence remasking) and stays disclosed.
- **Released code first.** dLLM-Cache and dKV-Cache select tokens by fixed top-k per step and have no threshold option. Patch ONLY the selection line (count = number of blanks with confidence >= 0.9, at least 1) and stop the block loop when the block has no blanks. Cache logic untouched. Labelled "released code, word-lock line patched".
  - Patch check (must pass before any full run): with threshold above 1 (top-1 each step) the patched code reproduces the existing one-token-per-step records of the unpatched code token for token.
- **Models:** LLaDA-8B-Instruct and LLaDA-1.5 first. Dream-7B only after its smoke run works (Dream needs the native reference loop at steps = length and thin wrappers for the released Dream code of Fast-dLLM v1/dream, dKV-Cache and dLLM-Cache).
- **Sets:** HumanEval (164), KodCode held (150), GSM8K held, MATH-108. Full sets (OPEN: confirm vs ~80 prompts per cell; the cost estimate below assumes full).
- **Clean rerun:** everything of this campaign is re-measured inside this directory, in one orchestration. Earlier records (results/model_transfer_20261113) stay untouched as history and are not mixed into any table of this campaign. Every job also runs the dense original on the first 20 prompts as a speed anchor, to remove the ~8% cross-run drift seen earlier.

### A2. Metrics (per model, set, arm)
| Metric | Definition |
|---|---|
| Speed | wall-clock speedup over the original decoder, paired over prompts with a bootstrap CI; tokens/s |
| FLOP cut | backbone GEMM + attention FLOPs vs the original (SureLock's convention); vocabulary head and any controller/projector cost reported separately; one counter (torch FlopCounterMode) for released code and our engine; measured on ~20 prompts per cell in a separate pass so its overhead does not touch speed |
| Call count | forward calls counted by a hook on the model (uniform across arms; several released generators only report a nominal step count) |
| Call time | mean ms per call; for our engine arms split into dense and cached calls (the fixed per-call cost, ~33 ms, is why a FLOP cut is not a speed cut; see dInfer in related_papers.md) |
| Accuracy | paired delta vs the original with its CI; says whether the CI includes 0 |
| Peak memory | from the existing per-record field |

The fastest arm with no detectable answer loss is named per cell. Tables sorted by speed.

## Part B. Study 6: representation cache x word lock grid (ESSENTIAL FURTHER TASK, deferred; do not drop)

Purpose: show that the two savings combine multiplicatively. Total time = calls x time per call; the word lock changes calls, the representation cache changes time per call. The decomposition is an identity; the grid tests whether the two factors are separable. Report per cell: speed, FLOP cut, accuracy (as the owner asked: simple), plus ONE extra line, the interaction ratio I = S(r,w) / (S(r,B0) x S(dense,w)) with a paired bootstrap CI. Expectation stated in advance: I slightly below 1 (with fewer calls per block the dense call at each block start is a larger share, so the cache saves less per call). The grid can falsify, not prove; the framing becomes "multiplicative up to a measured interaction" if I < 1.

- **Representation-cache axis:** baseline (dense original), the four published rules, R0 (the generalizable one). 6 entries.
- **Word-lock axis (established ones, released code first, our implementation if no code):** KLASS, EB-Sampler, Learn2PD, TraceLock (4 old); one NEW word lock the collaborator (Indira Duisembayeva) will supply, to be used when it arrives; and the original Conf-0.9. OPEN: is "original conf" the baseline word lock of the grid (making B0 not a column), or is it in addition to B0 (7 columns)? The earlier 6x6 assumed baseline = B0.
- **Blocked on:** the collaborator's word lock. Starts after Study 5 is in.
- **Size:** about 60 prompts per cell, LLaDA-8B on HumanEval first; second model only if it holds. Rough cost 10-15 GPU-h (only the B0 row/column is slow).
- **TraceLock** is used in this grid only; it stays out of the representation-cache artifact page.
- **Engine:** released code where it exists (patched only at the selection line if needed); otherwise our reproduction, validated against released-code numbers at the shared Conf-0.9 column from Study 5.
