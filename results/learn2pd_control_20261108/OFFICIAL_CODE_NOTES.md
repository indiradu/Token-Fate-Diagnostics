No Dream weights are shipped (the `dream/` folder has the model code only).

Where the official code differs from the task description / the paper text (all of these are implemented as the code does it unless stated):

1. **tau is applied to the sigmoid, strict.** `transfer_index = torch.sigmoid(block_logists) > accept_thres` (`generate.py`, `generate_learn2parallel`, `generate_l2p_eot`, `get_transfer_index`). The evaluation script uses `accept_thres=0.96`. We use the sigmoid in both decoders.
2. **L2PD is not "filter, else best blank".** The vanilla top-k schedule stays on: after the filter, `topk(confidence, k=num_transfer_tokens[j, i])` is added to `transfer_index` with steps == gen_length, i.e. one position per call. Every call writes (filter-accepted blanks) UNION (the single most confident blank). A "fallback share" is therefore not defined as for C-c; we report the share of calls on which the filter accepted nothing (only the forced word was written) and the share on which the forced word was outside the filter's set.
3. **The filter reads the whole block, written positions included.** Input = `x0_p[:, block_start:block_end]` (32 values, already-written slots too, whose confidence is the model's current prediction there), output one logit per slot; only still-masked slots are acted on. Consequence for caching: the official dual-cache call recomputes all 32 block rows. Our selective-cache engine normally caches rows written two or more calls ago, which would leave the filter without their confidences, so for L2PD (`SelectiveConfig.block_rows=True`) the engine computes every block row each call; rows/call is reported honestly (it is larger than S32:C-c's).
4. **EoT in the code is more aggressive than the paper's sentence ("once an end-of-text token is unmasked").** `generate_l2p_eot`: if the filter wrote an EOS (`x0 == 126081` and accepted) the sequence is cut after the first such position; otherwise, if ANY still-masked position anywhere in the sequence has argmax EOS, the sequence is cut after the most confident one (`end_token_conf.argmax`), although nothing was written there. Our truncation (all selective-cache cells and the twin) cuts after the first WRITTEN EOS/EOT. So our "L2PD+EoTP" is less aggressive than the official one; we did not implement the argmax-cut (it can discard text that the decoder would still have to write, so a comparison would mix a different decoder into the baseline).
5. **Training recipe: the notebook differs from the paper.** `train.ipynb`: AdamW lr 0.003, 40,000 full-batch epochs, 80/10/10 random row split (rows, not questions), validation threshold 0.9; the paper (v2) states lr 1e-3 and 5,000 epochs on 2,640 samples (40 from each of 66 FLAN types). The notebook imports `dream.model.small_model`. Our retraining follows the paper's numbers (lr 1e-3, <= 5,000 epochs) on a much smaller set (see README).
6. **Training data.** `generate_training_data.py` / `.sh`: FLAN `inputs` tokenised RAW (no chat template; the evaluation code applies the chat template for instruct models except HumanEval), `--steps 256 --gen_length 256 --block_length 32`, `--num_sample 40` per FLAN task. Reference answer = the standard one-token-per-step decode; the second pass is the EGP replay (per step, every block slot whose argmax equals the reference token is written, all 32 slots are labelled, a stuck guard writes the reference block when the block argmax repeats). Labels cover written slots too. The released weights were therefore fit on short FLAN answers (most 32-blocks are padding), not on math or code.
7. **Numerics.** The official confidence is softmax of the bf16 logits (float64 in the cache path) of the raw argmax (the mask token is not suppressed); ours is the repo convention (float32 softmax of the mask-suppressed argmax). Same convention in both of our arms; rejected-mask counts are logged for dense cells (`mask_rejected`).
